Advanced Extension: Cloud Hosting Architecture & Static vs. Dynamic Limitations
Analysis of hosting decoupling across Edge CDN and PHP/MySQL backend services
Cloud Strategy
🌐 Tier 1: Static Edge Hosting (GitHub Pages / Vercel)

Suitable for public-facing informational pages and static client applications.

  • Hosted Assets: index.html, css/, js/, pages/*.html.
  • Benefits: Global CDN distribution, SSL by default, zero hosting cost.
  • Limitations: No server-side PHP execution; read-only environment; database transactions and secure cookie sessions cannot run natively on static servers.
⚙️ Tier 2: Dynamic Cloud Backend (InfinityFree / Railway / Render)

Required for transactional processing, database persistence, and RBAC.

  • Hosted Modules: PHP 8.1+ scripts, MySQL database, session storage.
  • Cross-Origin Strategy: CORS headers in practical-13/api/events.php allow the static frontend to safely dispatch asynchronous Fetch CRUD requests to the remote backend.
  • Persistence: Permanent filesystem storage for event poster uploads.
